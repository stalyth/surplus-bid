# SurplusBid 范围表

日期：2026-10-23

阶段：W2 行走骨架与核心流程

项目一句话：**SurplusBid 让买卖双方的 Agent 通过公开链上竞价发现成交价格，并按确定性规则分配交易剩余。**

## 不可删除的核心主张

卖家底价与买家报价之间形成交易剩余：

```text
trade surplus = buyer bid - seller reserve
current demo price = reserve + floor(trade surplus / 2)
```

当前演示暂用中点定价，让卖家获得高于底价的增量，同时让买家保留低于其报价的差额。该公式是初步方案，
后续可以替换；稳定不变的要求是定价和费用规则在报价前公开并固定。Concordium
智能合约负责接收报价、选择赢家、计算成交价以及执行 CCD 分账和退款，使参与方能够独立核对规则、输入、结果和资金流向。

如果删除预先公开的确定性定价规则、链上赢家选择或链上分账退款，项目就退化为普通的竞价界面或支付演示，
因此这三项不能用占位逻辑替代。

## 本周核心流程

本周只完成一条可在三分钟内演示的主路径：

1. 卖家 Agent 创建一轮数字服务拍卖，设置服务标识、底价、容量和截止时间。
2. 两个买家 Agent 在截止前提交公开报价，并向合约存入报价金额。报价是买家的最高总支出上限。
3. 合约过滤低于底价的报价，按报价降序选择容量范围内的赢家；同价时链上序号较早者优先。
4. 截止后由任意账户调用 `finalize`。合约按中点公式计算成交价，退回落选者全部存款和赢家差额，并向卖家及平台付款。
5. 页面展示报价、赢家、交易剩余如何分配、四方资金变化、合约最终余额及 CCDExplorer 链接。

固定演示场景：底价 2 CCD、容量 1、A 报价并存入 4 CCD、B 报价并存入 6 CCD。预期结果为 B
成交价 4 CCD，交易剩余 4 CCD，平台费为交易剩余的 10%，由双方各承担 0.2 CCD；A 退回 4 CCD、
B 退回 1.8 CCD、卖家收到 3.8 CCD、平台收到 0.4 CCD，合约余额归零。

## 官方组件边界

首选验证 **x402 Agent-to-Agent payments**，但目前尚未证明它能与已有拍卖合约的 CCD
托管和结算合理衔接。下一步只验证一个问题：x402 在赢家确定后负责什么，以及它是否会与合约资金结算重复。

只有在以下条件同时满足时，x402 才进入核心流程：

- 使用真实官方实现完成一次可复现调用；
- 在主流程中承担明确且不可替代的职责；
- 不造成同一笔交易被合约和 x402 重复付款；
- 评委能看到请求、授权或支付结果的证据。

若验证后无法形成清晰链路，则改用 Agent Registry 与 Verified by Concordium badge，并在买家接受报价或服务交付前完成真实身份核验。选择结果必须记录为验证结论，不能把未跑通的集成写成已完成功能。

## Agent 的最小职责

MVP 不需要复杂 AI。Agent 只需执行一条真实、可解释的规则：

- 卖家 Agent：根据固定演示输入创建拍卖。
- 买家 A：预算允许时提交 4 CCD 报价。
- 买家 B：预算允许时提交 6 CCD 报价。
- 结算触发者：到达截止时间后请求 `finalize`。

界面必须明确显示这些是演示策略。固定规则可以作为行走骨架，但不能把人工按钮点击描述为完全自主 Agent。
当前演示底价固定为 2 CCD，竞价时长固定为 5 分钟。Seller Agent 以创建时的链上时间为基准计算截止时间。

未来 Seller Agent 只在一轮结束后，根据多轮历史成交、报价、交易剩余和当前库存生成下一轮底价及竞价时长；
不得修改已经开放报价的拍卖。“供需稳定时交易剩余逐渐趋近于 0”是待验证假设，不写成保证结果。

## 明确不做

- 不做多链、主网交易或真实资产演示。
- 不做多轮自主议价、复杂托管、争议仲裁或服务质量担保。
- 不做密封报价、零知识竞价或报价隐私承诺。
- 不做生产级身份、声誉和反欺诈系统。
- 不把链上成交等同于链下服务已经交付。
- 不把中点价格描述为客观的公允市场价格。
- 不为行走骨架引入数据库；先使用链上状态、链上交易和明确标注的本地 JSON。

## 本周完成标准

- 一条已写入 README 的命令启动项目所需进程。
- 页面能从卖家输入开始，走到两个买家报价、结算结果和链上证据。
- 交易剩余、成交价、退款、卖家收入、平台费用和网络费用分别展示。
- 核心步骤使用真实 Concordium Testnet 结果；占位内容明确标注 `placeholder`。
- 至少覆盖成功路径和一个失败路径，失败发生时不重复发送交易或丢失合约资金。
- 双买家 Testnet 验证未完成前，界面、README 和演示稿均明确标为待验证。
- 新费用规则完成实现和 Testnet 复验前，不把旧固定费用交易描述为新规则证据。
- x402 或替代官方组件完成真实、可复现且与业务流程有关的集成。
- 评委可以从页面打开对应 CCDExplorer 交易并核对合约实例、资金流向和最终状态。

## 范围变更规则

新增功能前依次回答：

1. 删除它后，评委还能否理解“Agent 竞价并分配交易剩余”的核心主张？
2. 它是否直接影响赛事门槛或评审标准？
3. 它是否阻塞当前端到端闭环？

如果第一题答案是“能”，且后两题答案是“否”，该功能移入“延后”或“愿景”，不进入本周核心流程。
