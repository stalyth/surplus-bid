# 最小拍卖结算验证

日期：2026-10-23。已完成本地 Wasm 测试，以及真实 Concordium Testnet 的空轮结束、单买家成交、分账与退款验证。
**双买家竞争与落选退款目前只通过本地测试，尚未在真实测试网完成。用户已要求在此停止验证。**
本地测试账户和余额为 `demo data`；测试网交易使用真实测试 CCD，但服务标识和报价为演示输入，不代表真实商品交易或链下服务已交付。

## 已确认规则

平台每笔成交向买家和卖家各收固定 **0.2 CCD**，合计 0.4 CCD，未成交不收平台费用。
这不是百分比收费。链的网络手续费另计，即使业务调用失败也可能产生网络费用。

买家报价 `bid` 时锁入 `bid + 0.2 CCD`。每个报价购买一份服务：

```text
price = reserve + floor((bid - reserve) / 2)
winner refund = bid - price
seller receives = price - 0.2 CCD
platform receives = 0.4 CCD
loser refund = bid + 0.2 CCD
```

全部以整数 microCCD 计算。底价至少 0.2 CCD，避免卖家净收入为负。
中点向下取整，舍入余量留在买家退款中。最大报价数为 16，每个账户（含别名）一次报价。
截止时拒绝新报价并允许任何账户发起结算；需要有人提交交易，不会自动执行。
固定规则及平台收款地址没有修改入口。

底价 2 CCD，容量 1，A 报价 4、B 报价 6：

| 项目 | CCD |
| --- | --- |
| A 存入 | 4.2 |
| B 存入 | 6.2 |
| B 成交价 | 4 |
| A 退回（含未使用的平台费用） | 4.2 |
| B 差额退款 | 2 |
| 卖家收到 | 3.8 |
| 平台收到 | 0.4 |
| 合约结算后余额 | 0 |

资金守恒：`4.2 + 6.2 = 4.2 + 2 + 3.8 + 0.4`。
测试同时逐个核对了真实 Wasm 执行产生的账户余额与本地网络费用，不仅检查计算函数。

## 实际运行与覆盖

在当前独立项目仓库中，从仓库根目录运行：

```sh
./scripts/check-contract.sh
```

原学习仓库实测构建成功；旧收退测试 4 组、拍卖测试 11 组全部通过，TypeScript 检查通过。
本仓库只迁移拍卖合约，因此当前检查命令构建拍卖 Wasm 并运行 11 组拍卖测试。
拍卖覆盖：

- 两买家资金闭环、固定费用与每个账户余额对账。
- 同价按链上序号优先；容量上限与多个成交的逐笔固定费用。
- 零报价、全部低于底价、等于底价、容量大于报价数。
- 截止前拒绝结算，截止瞬间拒绝报价并允许结算。
- 任意账户触发结算；重复结算不能再次付款，结束后不能报价。
- 零报价金额、少付或多付存款、超出报价数上限、同账户及别名重复报价。
- 不存在的平台账户在接收报价资金前拒绝；无效初始规则被具体错误码拒绝。
- 奇数 microCCD 的舍入、u64 金额边界、存款加法溢出。
- 最大 16 个报价可以结算；分别测试执行阶段和存储阶段额度耗尽，各接收账户、卖家应收款、合约资金与状态均回滚，随后可正常重试。执行阶段失败同时核对发起账户的模拟网络费用。

测试库限制：`concordium-smart-contract-testing` 4.4.0 在 `contract_update` 的
`changeset.persist` 失败分支提前返回，跳过末尾的账户扣费；本地实测的存储阶段额度耗尽因而出现报告费用与余额扣费不一致。
此路径只用于验证资金和状态回滚，不用于推断真实链上失败交易费用。
未修改或升级官方库；真实测试网失败费用仍需单独核验。
