# SurplusBid 演示故事板

日期：2026-10-23

目标时长：3 分钟以内

演示环境：Concordium Testnet

## 演示要证明的结论

**SurplusBid 让多个买家 Agent 竞争有限的数字服务，并由 Concordium 智能合约按照预先公开的规则选择赢家、分配交易剩余，最后完成可公开核验的 CCD 分账和退款。**

评委看完后应能确认：拍卖规则在报价前已经固定；赢家、成交价、费用和退款由同一个合约执行；页面上的结果可以通过 CCDExplorer 独立核验。

## 固定演示场景

| 项目 | 演示值 |
| --- | --- |
| 数字服务 | Priority AI Analysis |
| 服务说明 | 卖家 Agent 在当前时间窗口只能交付一份高优先级 AI 分析结果 |
| 容量 | 1 |
| 卖家底价 | 2 CCD |
| 竞价时长 | 创建后固定 5 分钟 |
| 买家 A 报价与存款 | 4 CCD |
| 买家 B 报价与存款 | 6 CCD |
| 当前演示定价 | `price = reserve + floor((winningBid - reserve) / 2)` |
| 赢家 | 买家 B |
| 成交价 | 4 CCD |
| 交易剩余 | `6 - 2 = 4 CCD` |
| 平台费 | `4 × 10% = 0.4 CCD` |
| 费用分担 | 买家 0.2 CCD，卖家 0.2 CCD |
| 最终资金结果 | A 退回 4；B 退回 1.8；卖家收到 3.8；平台收到 0.4 CCD |

中点定价只是本次 MVP 的初步方案，页面必须标注“当前演示定价规则”，不能把它描述为永久机制或客观公允价格。更换定价机制时，只能作用于尚未开始报价的新拍卖。

## 费用和资金规则

```text
surplus = winningBid - reserve

if surplus < price × 10%:
    platformFee = 0
else:
    platformFee = surplus × 10%

buyerFee = platformFee / 2
sellerFee = platformFee / 2
```

- 刚好等于免收阈值时正常收费。
- 只有成交时收费；未中标或未成交不收平台费。
- 报价是买家的最高总支出上限，买家只向合约存入报价金额。
- 合约必须保证 `price + buyerFee <= winningBid`。
- 赢家退款为 `winningBid - price - buyerFee`；卖家实收为 `price - sellerFee`；未中标者退回全部报价。
- 网络交易费单独展示，不计入平台费。
- 合约使用整数 microCCD。百分比及双方平分遇到余数时的舍入规则尚待实现前确定并测试。

### 第 1 幕：规则已在报价前固定

**画面**

- 打开一个已在 Testnet 创建且仍处于报价期的真实拍卖。
- 展示服务名称、服务说明、容量、底价、固定 5 分钟竞价时长、具体截止时间、最大报价数、当前定价规则和平台费规则。
- 展示 Testnet、卖家账户、拍卖 ID、合约实例和创建交易链接。
- “报价”按钮可用，“结算”按钮在截止前不可用。

**Agent 与用户动作**

- 卖家 Agent 根据服务容量和最低可接受价格生成拍卖参数。
- 卖家在钱包中核对并确认创建交易。三分钟现场演示不重新部署模块；本幕读取事先创建的真实拍卖及其创建交易。

**旁白要点**

> 卖家 Agent 只有一份高优先级分析容量。底价、截止时间、定价和费用规则已经写入本轮拍卖，买家报价后不能被临时修改。

**评委应相信**

拍卖规则先于报价确定，平台不能在看到买家报价后改变规则。

**证据与通过条件**

- 创建交易已最终确认。
- 页面从合约读取的规则与界面展示一致。
- 创建交易、合约实例和后续交易使用同一个拍卖 ID。

### 第 2 幕：两个买家 Agent 公开报价

**画面**

- 买家 A 的演示策略生成 4 CCD 报价。
- 买家 B 的演示策略生成 6 CCD 报价。
- 用户分别在钱包核对并确认两笔 `bid` 交易。
- 页面展示两笔报价的确认状态和链上顺序，不在截止前宣布赢家。

**旁白要点**

> 两个买家 Agent 按各自预算生成报价。报价就是最高总支出上限，CCD 在截止前由合约锁定；本次 MVP 使用公开报价。

**评委应相信**

两笔报价是真实链上输入，资金已经由拍卖合约控制，报价顺序可以独立核对。

**证据与通过条件**

- A、B 的报价交易均最终确认。
- 合约状态中存在两笔报价及确定的链上顺序。
- 合约余额等于两笔报价存款之和 10 CCD，网络费另计。

### 第 3 幕：截止后由合约结算

**画面**

- 截止前尝试结算时，按钮不可用或合约明确拒绝。
- 截止后“结算”按钮启用，由卖家在演示中触发；协议允许任何账户调用 `finalize`。
- 钱包显示本次调用转入 0 CCD，仅支付网络费。
- 交易确认后展示 B 中标、当前中点成交价 4 CCD，以及交易剩余和费用计算过程。

**旁白要点**

> 区块链不会在截止时自动运行。截止时间定义了合约允许报价和允许结算的边界；截止后任何账户都能触发结算，但触发者不能修改赢家、价格或分账。

**评委应相信**

截止时间具有链上约束，结算触发者只是启动既定规则，不能决定结果。

**证据与通过条件**

- B 是最高合格报价，容量 1，因此 B 中标。
- 当前演示成交价为 4 CCD，交易剩余为 4 CCD。
- 交易剩余不小于成交价的 10%，因此收取 0.4 CCD 平台费，买卖双方各承担 0.2 CCD。
- A 收回 4 CCD；B 收回 1.8 CCD；卖家收到 3.8 CCD；平台收到 0.4 CCD；合约最终余额为 0。
- 拍卖状态变为 `Finalized`。

## 网络异常备用路径

若现场 Testnet、公共节点或中国大陆代理环境不稳定，页面读取一笔事先真实完成的 Testnet 拍卖：

- 明确标注“预先完成的真实 Testnet 交易”，不能伪装成刚刚执行成功。
- 仍从链上读取最终状态，并打开对应 CCDExplorer 页面。
- 不用 mock 数据替代链上结果；读取失败时显示可识别的失败状态和原因。

## x402 边界

本版资金主线由 Concordium 拍卖合约完成 CCD 托管、分账和退款。若同时再通过 x402 收取同一笔服务款，会造成重复支付。因此：

- 当前故事板不把 x402 描述为已集成能力。
- x402 暂定为服务交付接口的候选方案，并明确标注“需要验证”。
- 下一步需要验证 x402 能否使用拍卖结算证明授权赢家访问 AI 分析服务，以及这是否符合官方协议流程。
- 在形成真实、可复现且不重复收费的链路前，x402 不进入本次资金结算演示。
