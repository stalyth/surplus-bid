# 最小公开拍卖验证

仅限 Concordium Testnet。单卖家、单轮、单个买家账户一次报价、最多 16 个报价。
一个买家报价购买一份服务，容量决定最多成交几份；同价按链上接收序号优先。
同一账户的地址别名不能绕过一次报价限制。报价公开。

## 已固定的费用与资金规则

每笔成交买家和卖家各付 **0.2 CCD** 平台费用，合计 **0.4 CCD**；未成交不收平台费用。
创建拍卖时固定卖家、平台收款地址、底价、容量、报价上限、服务标识和截止时间，无修改入口。
底价至少 0.2 CCD；截止前可以报价，恰好到截止时不再报价，允许任意账户触发结算。
合约不会自行定时结算。

所有金额以整数 microCCD 计算（0.2 CCD = 200000 microCCD）：

| 项目 | 计算 |
| --- | --- |
| 买家存款 | 报价 + 0.2 CCD |
| 成交价 | 底价 + floor((报价 - 底价) / 2) |
| 中标买家退款 | 报价 - 成交价 |
| 卖家收入 | 成交价 - 0.2 CCD |
| 平台收入 | 0.4 CCD / 每个中标报价 |
| 未中标退款 | 报价 + 0.2 CCD |

中点向下取整，舍入余量留给买家。网络交易手续费由链另计。
低于底价但非零的报价可以提交，结算时全额退回并且不收平台费用。
不存在的费用接收账户会导致报价在保留资金前拒绝。

`init` 创建拍卖；`bid` 的参数是报价 Amount，附带金额必须恰好为报价加 0.2 CCD；
`finalize` 在截止后一次性确定结果并付款；`view` 返回规则、报价、固定费用和结算明细。
结束状态明确区分 `Settled` 与 `NoSale`。不允许重复结算或结束后报价。
仅向账户转出 CCD；结算若失败，资金和状态整体回滚，可重新调用原拍卖结算。

## 运行

从仓库根目录执行：

```sh
./scripts/check-contract.sh
```

命令构建本拍卖的实际 Wasm 并执行集成测试。
复用已获准的 Rust 1.85.1 / cargo-concordium 4.2.0 / concordium-std 10.1.0 /
concordium-smart-contract-testing 4.4.0，不新增 Node 依赖。
本机验证时使用的工具链缓存位于 `/private/tmp/concordium-toolchain`；工具链本身不进入仓库。

测试中的账户与余额是明确的本地测试数据；它们不证明真实 Testnet 的多账户竞价已完成。
本拍卖模块已部署到测试网：实例 `<13004,0>` 验证空轮 `NoSale`，`<13005,0>` 验证单买家成交、差额退款、卖家与平台分账及余额归零；只读重复结算按 `Closed` 拒绝。
双买家竞争与落选退款仍未在真实测试网完成。原实例 `<13003,0>` 仅是旧收退 spike。
交易、实测网络费用、余额对账和未验证部分见 [拍卖验证记录](../../../docs/06-拍卖结算验证.md)。用户已要求停止继续验证，未新建下一轮。
未接入 x402 / Agent Registry、自动 Agent 报价、价格统计面板；未做安全审计。
